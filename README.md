# تفاعل (tafa3l)

منصة خفيفة لإنشاء **أسئلة تفاعلية واستطلاعات حية** — على غرار Mentimeter — مصمّمة للمدرب أو المعلم:
يجهّز أسئلته، يعرض رمز QR، فيدخل المتدربون من جوالاتهم ويجيبون مباشرة، بينما يتابع هو التقدّم والإحصاءات على لوحة تحكم حيّة.

> **نتائج المشاركين مؤقتة بالكامل.** إجابات الطلاب ونقاطهم في ذاكرة الخادم (RAM) فقط، وتُحذف
> تلقائياً بعد ٣٠ دقيقة من إنهاء الجلسة، أو بعد ٣ ساعات من الخمول، أو فور إعادة تشغيل الخادم.
> الدائم الوحيد — وباختيار المدرب — هو **حسابه وأسئلته المحفوظة**، وهي محتواه هو لا بيانات طلابه.
> ويبقى استخدام التطبيق بلا حساب متاحاً بالكامل.

---

## التشغيل

```bash
npm install
npm start          # http://localhost:3000
```

> **مهم:** التطبيق يحتاج خادم Node يعمل. فتح ملفات `public/*.html` مباشرة من المجلد (بروتوكول `file://`)
> أو من خادم ملفات ثابت لن ينجح: ستظهر الصفحات لكن إنشاء الجلسات والاتصال المباشر لن يعملا.
> في هذه الحالة يعرض التطبيق شريطاً تحذيرياً يشرح الحل بدل رسالة خطأ غامضة.
> القوالب الجاهزة تعمل دائماً لأنها محمّلة مع الصفحة بلا أي طلب شبكة.

للتطوير مع إعادة التحميل التلقائي:

```bash
npm run dev
```

الاختبارات (تكامل حقيقي عبر HTTP + WebSocket):

```bash
npm test
```

متغيرات البيئة: `PORT` (افتراضياً `3000`).

## النشر على الإنترنت

التطبيق يحتاج **عملية Node دائمة** لسببين: خادم WebSocket للاتصال المباشر، وحالة الجلسة في ذاكرة العملية.

### ✅ منصات تعمل (بلا أي تعديل)

| المنصة | الطريقة |
| --- | --- |
| **Render** | اربط المستودع — ملف `render.yaml` جاهز ([التفاصيل أدناه](#إعدادات-render-بالتفصيل)) |
| **Railway** | اربط المستودع؛ يكتشف `npm start` تلقائياً |
| **Fly.io** | `fly launch` ثم `fly deploy` — يستخدم `Dockerfile` الجاهز |
| **Koyeb / Cloud Run / VPS** | من `Dockerfile` مباشرة، أو `npm ci && npm start` خلف Nginx |

المنصة تحقن `PORT` تلقائياً والتطبيق يلتزم به. لا حاجة لأي قاعدة بيانات أو متغيرات أخرى.

### ❌ منصات لا تصلح

**Vercel · Netlify · GitHub Pages · Cloudflare Pages** (بوضعها الثابت/serverless):

- لا تستضيف خادم WebSocket، فالاتصال المباشر لن يعمل.
- الدوالّ serverless قصيرة العمر ولا تتشارك الذاكرة، فحالة الجلسة تضيع بين الطلبات.

النتيجة عليها: **تظهر الصفحات وتفشل كل طلبات `/api`** — القوالب تعمل (لأنها محمّلة مع الصفحة)
لكن إنشاء جلسة يفشل. التطبيق يكتشف هذه الحالة ويعرض شريطاً يشرح السبب بدل رسالة خطأ غامضة.

> لتشغيله على Vercel يلزم استبدال طبقة الاتصال المباشر بخدمة خارجية (Ably/Pusher) ونقل الحالة إلى مخزن
> خارجي مثل Redis — وهي إعادة بناء لجوهر التطبيق، لذلك التوصية هي استخدام إحدى المنصات أعلاه.

## إعدادات Render بالتفصيل

### ١. نوع الخدمة (الأهم)

اختر **Web Service** وليس Static Site. الفرق حاسم:
Static Site تخدم ملفات فقط، فتظهر صفحات التطبيق لكن كل `/api` يفشل ولا يعمل أي اتصال مباشر.

| الحقل | القيمة |
| --- | --- |
| Type | **Web Service** |
| Runtime | Node |
| Build Command | `npm ci` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |

لا تضبط `PORT` يدوياً — Render يحقنه والتطبيق يلتزم به.

### ٢. متغيرات البيئة الموصى بها

| المتغير | القيمة | الأثر |
| --- | --- | --- |
| `NODE_ENV` | `production` | تخزين مؤقت للملفات الثابتة |
| `KEEP_ALIVE_MINUTES` | `10` | نبضة تمنع نوم الخدمة أثناء المحاضرة |
| `SESSION_IDLE_MINUTES` | `300` | مدة بقاء الجلسة بلا نشاط (٥ ساعات) |
| `SESSION_ENDED_MINUTES` | `60` | مدة بقاء نتائج جلسة انتهت |
| `DATABASE_URL` | رابط Postgres | لازم لبقاء حسابات المدربين وأنشطتهم بعد كل نشر |

كلها موجودة في `render.yaml`، فإن ربطت المستودع كـ Blueprint تُضبط تلقائياً.

### ٣. مشكلة النوم بعد ١٥ دقيقة (وحلّها)

الخطة المجانية على Render **توقف الخدمة بعد ١٥ دقيقة بلا طلبات واردة**، وإيقافها يمسح
كل الجلسات لأن التخزين في الذاكرة. هذا يعني أن جلسة بدأتها في أول المحاضرة قد تختفي في وسطها.

**الحل المدمج:** الخادم يرسل لنفسه نبضة خفيفة كل ١٠ دقائق عبر عنوانه العام
(`RENDER_EXTERNAL_URL` الذي يضبطه Render تلقائياً) — **لكن فقط ما دامت هناك جلسة قائمة**،
حتى لا تُستهلك ساعات الخطة المجانية بلا داعٍ. فما دام لديك نشاط مفتوح، لن تنام الخدمة.

للتحقق من أنها مفعّلة، افتح `https://<موقعك>/api/health` وابحث عن:

```json
{ "ok": true, "config": { "keepAlive": "https://<موقعك>", "keepAliveMinutes": 10 } }
```

إن كانت `keepAlive` تساوي `null` فالنبضة معطّلة — أضف `KEEP_ALIVE_URL` بعنوان موقعك يدوياً.

> الخطة المجانية تمنح ٧٥٠ ساعة شهرياً. النبضة تعمل أثناء الجلسات فقط، لكن إن كنت تستخدم
> التطبيق يومياً وبكثافة ففكّر في أرخص خطة مدفوعة — فهي لا تنام أصلاً وتزول المشكلة تماماً.

### ٤. حلّ مشكلة «Not Found»

هذه الكلمة الإنجليزية **لا يُخرجها التطبيق إطلاقاً** — كل رسائله عربية، وأي مسار مجهول يعيد
الصفحة الرئيسية، ورابط الدخول `/j/<الرمز>` يحوّل دائماً إلى صفحة المشاركة. فإن رأيتها فهي من Render.

للتشخيص في ثانية واحدة:

```bash
curl -I https://<موقعك>/api/health
```

| ما تراه | المعنى | العلاج |
| --- | --- | --- |
| ترويسة `x-render-routing: no-server` | لا توجد خدمة تعمل على هذا العنوان | الخدمة موقوفة أو فشل نشرها أو نوعها Static Site |
| `404` وردّ HTML من Render | غالباً Static Site | أعد إنشاءها كـ Web Service |
| `200` مع `{"ok":true}` | الخادم يعمل | المشكلة في الجلسة نفسها لا في النشر |

وإذا كان الخادم يعمل لكن الرابط لا يفتح جلستك، فالسبب أن الجلسة نفسها اختفت: إما لأن الخدمة نامت
وأُعيد تشغيلها (راجع القسم أعلاه)، أو لأن نشراً جديداً أعاد تشغيل العملية. في هذه الحالة تظهر
للمتدرب رسالة عربية واضحة «لم نعثر على الجلسة» — أنشئ جلسة جديدة واعرض رمزها.

> **تذكّر:** رمز الجلسة صالح ما دامت العملية تعمل. أي إعادة نشر تمسح الجلسات القائمة —
> فلا تنشر تحديثاً أثناء محاضرة جارية.

## كيف يعمل؟

### للمدرب
1. افتح `/host.html` → ابنِ النشاط (أو ابدأ من قالب جاهز).
2. اضغط **ابدأ الجلسة** → يظهر رمز QR + رمز من ٦ أرقام.
3. تحكّم بالعرض: إغلاق الإجابة، كشف النتائج، لوحة الترتيب، السؤال التالي.
4. تابع **لوحة التحكم**: نسبة التفاعل، دقة كل سؤال، تقدّم كل مشارك، متوسط زمن الإجابة.
5. عند الانتهاء يمكنك **تنزيل النتائج** كملف JSON إن أردت الاحتفاظ بها (الخادم لا يحفظ شيئاً).

> مفتاح المضيف (`hostToken`) يُحفظ في `localStorage` على متصفح المدرب فقط. من يملكه يتحكم بالجلسة — لذلك لا يمكن استئناف جلسة من جهاز آخر.

### من ينقل إلى السؤال التالي؟ (يُختار عند الإنشاء)

| الوضع | ماذا يحدث | متى تستخدمه |
| --- | --- | --- |
| 🎛️ **المدرب** | أنت تنقل الشرائح وتتحكم بالإيقاع (الافتراضي) | الشرح والمناقشة بين الأسئلة |
| ⏱️ **تلقائي** | الجميع معاً، وينتقل وحده بعد عرض النتائج بمدة تحدّدها (٣–١٥ ثانية) | مسابقة سريعة بلا توقف |
| 🏃 **حر** | كل متدرب يتقدّم بسرعته: يجيب، يرى نتيجته، ويضغط «التالي» | واجب فردي أو استبيان أو صفوف كبيرة |

في الوضع الحر يرى المدرب لوحة مباشرة: أين وصل كل متدرب (`٢/٣`)، من أنهى، ونتائج أي سؤال بالتصفّح بينها.
ولكل متدرب مؤقّته الخاص يبدأ لحظة فتحه للسؤال، وإن انتهى وقته يتابع إلى التالي بلا عقوبة.

**البدء التلقائي 🚀** (مفعّل افتراضياً في الوضع الحر): ينطلق المتدرب بمجرد دخوله — **لا ينتظر المدرب
إطلاقاً**، لا في البدء ولا في الانتقال. أطفئ الخيار إن أردت أن يبقى الجميع في القاعة حتى تضغط «بدء».

### نظام النقاط والتحفيز

**احتساب النقاط** (يُختار عند الإنشاء):

| الوضع | القاعدة |
| --- | --- |
| ⚡ **بالسرعة** | كاملة للإجابة الفورية وتتناقص حتى نصف القيمة عند آخر ثانية (الافتراضي) |
| 🎯 **ثابتة** | نفس النقاط لكل إجابة صحيحة مهما كانت السرعة — أعدل للمتدربين البطيئين في القراءة |
| 🕊️ **بلا نقاط** | تعلّم بلا منافسة: تختفي النقاط والترتيب تماماً |

**علامة كل سؤال:** يضع المدرب العلامة التي يريدها لكل سؤال بحرية (٠ إلى ١٠٠٠٠)، مع أزرار سريعة للقيم الشائعة.
سؤال بعلامة ٠ يبقى في النشاط لكنه بلا رصيد.

**شرح الإجابة الصحيحة 💡** (اختياري): لكل سؤال حقل شرح، وعند تفعيل «إظهار الإجابة الصحيحة» في إعدادات
النشاط يرى المتدرب — بعد إجابته فقط — الإجابة الصحيحة وسببها. الشرح **لا يُرسل إلى المتصفح إطلاقاً** قبل
أن يجيب، فلا يمكن استخراجه مسبقاً. وإن أطفأ المدرب الخيار فلا يُكشف شيء قبل عرض النتائج للجميع.

**مضاعف السلاسل 🔥** (اختياري): كل إجابة صحيحة متتالية تزيد النقاط ١٠٪ حتى سقف ٥٠٪ —
فالمتدرب الذي يجيب ٤ صحيحات متتالية يأخذ ×1.3 على الرابعة. يظهر المضاعف للمتدرب فور إجابته.

**الأوسمة 🏅** تُحسب في النهاية من الأداء الفعلي، وتمنح كل متدرب سبباً للفخر لا يلتقطه الترتيب وحده:

| الوسام | يستحقه |
| --- | --- |
| 🎯 دقة كاملة | أجاب على سؤالين مصحّحين فأكثر وكلها صحيحة |
| ⚡ الأسرع إجابةً | أقل متوسط زمن بين من أجابوا على نصف الأسئلة فأكثر |
| 🔥 أطول سلسلة | صاحب أطول سلسلة صحيحة (٣ فأكثر) |
| 💪 أجاب على كل الأسئلة | لم يفوّت سؤالاً واحداً |
| 🚀 أسرع من بدأ | الأكثر سبقاً إلى الإجابة قبل الجميع |

**الصعود والهبوط:** بين الأسئلة يرى المتدرب «⬆ صعدت ٣ مراكز» أو «⬇ نزلت مركزاً».

### التنقّل

- **المتدرب:** زر 🚪 للخروج من النشاط (بتأكيد أثناء الجلسة)، ثم يعود للصفحة الرئيسية.
- **المدرب:** زر 🏠 للصفحة الرئيسية — مغادرة الصفحة **لا تُنهي الجلسة**، وتستطيع استئنافها من
  «استئناف جلستي السابقة». وفي شاشة النهاية أزرار «نشاط جديد» و«الصفحة الرئيسية».
- إنهاء الجلسة أو حذفها يبقى قراراً صريحاً من المدرب (زر الإنهاء 🏁 أو الحذف 🗑).

### حساب المدرب ونشاطاته المحفوظة 🔐

الحساب اختياري تماماً — كل شيء يعمل بدونه، لكنه يحفظ أنشطتك لتعيد استخدامها.

1. **دخول أو حساب جديد** من `/login.html` (بريد + كلمة مرور).
2. **الحفظ تلقائي**: أي نشاط تطلقه وأنت مسجّل الدخول يُحفظ في حسابك فوراً — لا يحتاج زر حفظ،
   وإعادة إطلاق نفس النشاط تحدّثه بدل تكديس نسخ. (زر «💾 حفظ في حسابي» ما زال موجوداً للحفظ دون إطلاق.)
3. **إنهاء الجلسة أو إيقافها لا يحذف النشاط** — يبقى في حسابك جاهزاً لإعادة الإطلاق متى شئت.
4. صفحة **«📚 نشاطاتي»** (`/host.html#/mine`) تعرض كل أنشطتك مع عدد الأسئلة ووضع التقدّم وتاريخ آخر تعديل، ولكل نشاط:
   - **🚀 إطلاق جلسة** — يفتح جلسة مباشرة جديدة برمز QR.
   - **✏️ فتح وتعديل** — يحمّله في المحرّر.
   - **📄 استنساخ** — نسخة مستقلة تعدّلها دون المساس بالأصل.
   - **🗑 حذف** — نهائياً بعد تأكيد.
   - إن كان له جلسة تعمل الآن تظهر شارة **«مباشر»** مع زر **«↩ العودة للجلسة»**.

**الأمان:** كلمة المرور تُخزَّن مجزَّأة بـ scrypt بملح عشوائي لكل مستخدم — لا تُحفظ كنص صريح أبداً.
الجلسة عبر كوكي `HttpOnly` + `SameSite=Lax` (و`Secure` على https)، ومحاولات الدخول الفاشلة محدودة.
ولا يستطيع مدرب رؤية أنشطة غيره أو تعديلها أو إطلاقها — الملكية مفحوصة على الخادم في كل مسار.

**المحفوظ:** عنوان النشاط وإعداداته وأسئلته فقط. **غير المحفوظ:** أسماء الطلاب، إجاباتهم، نقاطهم، وأي نتيجة.

#### الربط بـ Supabase (موصى به ومجرَّب) 🟢

Supabase هي Postgres، فالتطبيق يعمل معها **بلا أي تعديل في الكود** — يكفي `DATABASE_URL`.

1. من لوحة Supabase: **Project Settings ← Database ← Connection string**.
2. اختر تبويب **Session pooler** ⚠️ ولا تختر «Direct connection».
3. انسخ الرابط، واستبدل `[YOUR-PASSWORD]` بكلمة مرور قاعدة البيانات.
4. ضعه في متغيّر البيئة `DATABASE_URL` على Render (أو أي منصة).

الجداول (`users`, `activities`, `auth_sessions`) تُنشأ تلقائياً عند أول تشغيل.

> **لماذا Session pooler تحديداً؟** الاتصال المباشر (`db.<ref>.supabase.co`) صار **IPv6 فقط**،
> و Render لا يوفّر IPv6 صادراً — فيفشل الاتصال. الـ Pooler يعمل على IPv4
> (`aws-0-<region>.pooler.supabase.com`). التطبيق يكتشف هذا الخطأ تحديداً ويطبع الحل.
>
> وإن كانت كلمة المرور تحوي رموزاً خاصة فرمِّزها في الرابط (`@` تصبح `%40`).

**للتأكد بعد النشر** افتح `/api/health` وابحث عن:

```json
{ "storage": { "kind": "postgres", "durable": true, "error": null } }
```

لو ظهر `"kind": "file"` فحقل `error` يشرح السبب بالضبط. التطبيق **لا يتوقف** عند فشل قاعدة البيانات —
تبقى الجلسات الحية تعمل، ويتحول تخزين الحسابات إلى ملف مؤقت مع تحذير ظاهر في «نشاطاتي».

مشروع هذا التطبيق على Supabase: **`tafa3l`** (المعرّف `vymuzlxguhwpjxrictac`، منطقة `eu-central-1`)
وجداوله الثلاثة مُنشأة مسبقاً، ومُفعّل عليها RLS بلا سياسات — فلا تُقرأ عبر واجهة Supabase العامة،
والتطبيق يصل إليها باتصال Postgres مباشر لا عبر PostgREST.

**لاختبار الربط قبل النشر** من جهازك:

```bash
DATABASE_URL='postgres://...pooler.supabase.com:5432/postgres' npm run test:pg
```

يشغّل ١٥ اختباراً على قاعدتك الفعلية: البقاء بعد إعادة التشغيل، عزل الملكية، والحسابات كاملة.

#### التخزين الدائم عند النشر

| الإعداد | السلوك |
| --- | --- |
| بلا `DATABASE_URL` | ملف JSON تحت `DATA_DIR` (افتراضياً `./data`) — مناسب للتطوير المحلي وللخوادم ذات قرص دائم |
| مع `DATABASE_URL` | Postgres (تُنشأ الجداول تلقائياً) — **الخيار الصحيح للنشر** |

> على استضافة بقرص مؤقت (مثل خطة Render المجانية) يضيع ملف JSON مع كل نشر. لذلك يعرض التطبيق
> تحذيراً في «نشاطاتي» ويكشف الحالة في `/api/health`. اضبط `DATABASE_URL` لقاعدة Postgres
> (Render Postgres أو Supabase أو Neon) لتبقى الحسابات والأنشطة.

### استيراد الأسئلة من JSON (مع مساعد ذكي) ⚡

في صفحة الإنشاء بطاقة «حوّل JSON إلى نشاط»: الصق JSON فيه العنوان والإعدادات والأسئلة، واضغط
**«تحويل إلى تفاعلي»** فيتحول إلى نشاط كامل قابل للتعديل والإطلاق.

- زر **«🤖 نسخ برومبت المساعد»** يعطيك تعليمات جاهزة تلصقها في أي مساعد ذكي (ChatGPT، Claude، Gemini…)
  فيولّد لك JSON صالحاً من أي موضوع أو درس. النص نفسه في [docs/ai-quiz-prompt.md](docs/ai-quiz-prompt.md).
- المحلّل متسامح مع مخرجات المساعدات: أسوار الشيفرة ```json، كلام قبل الكائن وبعده، الخيارات كنصوص،
  الإجابة الصحيحة بنص الخيار أو فهرسه أو حرفه (A/أ)، أسماء أنواع بديلة (multiple_choice، tf، rating…)،
  و«صح/خطأ» بالعربية. الأسئلة غير الصالحة تُتجاهل بتنبيه بدل إفشال الاستيراد كله.
- زر **«📋 مثال»** يملأ الصندوق بنموذج يوضح الصيغة.

### المتعة والتفاعل
- **عدّاد «استعد ٣٢١»** متزامن على كل الشاشات قبل الأسئلة المؤقتة.
- **تفاعلات فورية:** يرسل المتدرب 👏 🔥 😂 😮 ❤️ 🤔 فتطير على شاشة العرض (بلا نسبتها لأحد، مع حدّ لمنع الإغراق).
- **أصوات** خفيفة مولّدة برمجياً (بلا ملفات) للدخول والتصحيح والعدّ التنازلي، مع زر كتم 🔇.
- **قصاصات ورق** عند الإجابة الصحيحة وعند ختام النشاط، و**منصة تتويج** للأوائل الثلاثة.
- **سلاسل الإجابات** 🔥 وشدّ في الثواني الخمس الأخيرة (نبض صوتي ولون تحذيري).
- **تجربة سريعة بضغطة واحدة** من الصفحة الرئيسية لتجريب كل شيء دون تجهيز أسئلة.

> كل المؤثرات تحترم `prefers-reduced-motion`، والصوت مطفأ يبقى مطفأ بين الجلسات.

### للمشارك
1. يمسح رمز QR أو يدخل الرمز في الصفحة الرئيسية.
2. **وضع الاسم:** يكتب اسمه أو كنيته ويحصل على أفاتار SVG عشوائي (يمكنه تغييره بزر النرد).
3. **الوضع المجهول:** إن أطفأ المدرب خيار «طلب الاسم»، يدخل مباشرة بلا اسم ولا تُنسب إجابته لأحد.
4. يجيب، فيرى نتيجته فوراً (صح/خطأ + النقاط) ثم النتائج المجمّعة.

إن انقطع الاتصال يُعاد الوصل تلقائياً وتُستعاد الحالة والنقاط عبر `sessionStorage`.

## أنواع الأسئلة

| النوع | الوصف | نقاط؟ |
| --- | --- | --- |
| `mc` | اختيار من متعدد (حتى ٨ خيارات، يدعم إجابات صحيحة متعددة) | ✅ |
| `truefalse` | صح / خطأ | ✅ |
| `poll` | استطلاع رأي بلا إجابة صحيحة | ✖ |
| `scale` | مقياس رقمي (مثل ١..٥) — سلايدر سحب أفقي مع وصف للطرفين | ✖ |
| `word` | سحابة كلمات (كلمة قصيرة تتجمّع حسب التكرار) | ✖ |
| `open` | إجابة نصية مفتوحة | ✖ |

**احتساب النقاط:** الإجابة الصحيحة الفورية تعطي نقاط السؤال كاملة، وتتناقص كلما تأخّرت حتى نصف القيمة عند آخر
ثانية: `points × (0.5 + 0.5 × الوقت المتبقي ÷ المدة)`. بلا مؤقّت تُعطى النقاط كاملة دائماً.

**عدّاد «استعد ٣٢١»:** قبل كل سؤال مؤقّت يظهر عدّاد قصير متزامن مع الخادم على كل الشاشات، ولا يبدأ حساب
الزمن إلا بعد انتهائه — فينطلق الجميع من نفس الخط مهما اختلفت سرعة أجهزتهم. يمكن إطفاؤه من إعدادات النشاط.

## واجهة REST

| الطريقة | المسار | الوصف |
| --- | --- | --- |
| `POST` | `/api/sessions` | إنشاء جلسة ← `{ code, hostToken, joinUrl }` |
| `GET` | `/api/sessions/:code` | معلومات عامة (للتحقق من الرمز قبل الدخول) |
| `PUT` | `/api/sessions/:code` | تعديل الأسئلة قبل البدء (يتطلب مفتاح المضيف) |
| `GET` | `/api/sessions/:code/dashboard` | الإحصاءات الكاملة (يتطلب مفتاح المضيف) |
| `GET` | `/api/sessions/:code/export` | تنزيل النتائج JSON (يتطلب مفتاح المضيف) |
| `DELETE` | `/api/sessions/:code` | إنهاء الجلسة ومحو بياناتها فوراً |
| `GET` | `/api/qr?text=…` | رمز QR بصيغة SVG |
| `GET` | `/j/:code` | رابط الدخول المختصر (هدف رمز QR) |

مفتاح المضيف يُمرَّر عبر الترويسة `X-Host-Token` أو المعامل `?hostToken=`.

### رسائل WebSocket (`/ws`)

**من المشارك:** `join` · `rejoin` · `answer` · `next` (الوضع الحر) · `reaction` · `leave`
**من المضيف:** `host:hello` · `host:start` · `host:skip` · `host:prev` · `host:goto` · `host:lock` · `host:results` · `host:leaderboard` · `host:end` · `host:kick` · `host:dashboard`
**من الخادم:** `state` · `joined` · `dashboard` · `reaction` · `answer:accepted` · `answer:rejected` · `session:closed` · `kicked` · `error`

## الحدود والحماية

- ٣٠٠ مشارك و٦٠ سؤالاً كحد أقصى لكل جلسة، و٥٠٠ جلسة متزامنة للخادم.
- كل المدخلات تُقصّر وتُنظّف من محارف التحكم على الخادم.
- الإجابة الصحيحة **لا تُرسل** للمشارك قبل كشف النتائج.
- في الوضع المجهول لا يُرسل اسم أو أفاتار مع الإجابات المفتوحة إطلاقاً.
- إجابة واحدة لكل مشارك لكل سؤال، وتُرفض بعد إغلاق السؤال.
- المشارك يُعرَّف بمفتاح سري عشوائي؛ لا يمكن انتحال هوية مشارك آخر.

## الملاحظات

- التطبيق يحتاج WebSocket — خلف بروكسي عكسي فعّل تمرير الترقية (`Upgrade`/`Connection`).
- عند تعدد نسخ الخادم يجب تثبيت الجلسة على نسخة واحدة (الحالة في ذاكرة العملية).
