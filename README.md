# Tapio

منصة خفيفة لإنشاء **أسئلة تفاعلية واستطلاعات حية** — على غرار Mentimeter — مصمّمة للمدرب أو المعلم:
يجهّز أسئلته، يعرض رمز QR، فيدخل المتدربون من جوالاتهم ويجيبون مباشرة، بينما يتابع هو التقدّم والإحصاءات على لوحة تحكم حيّة.

> **نتائج المشاركين مؤقتة بالكامل.** إجابات الطلاب ونقاطهم في ذاكرة الخادم (RAM) فقط، وتُحذف
> تلقائياً بعد ٣٠ دقيقة من إنهاء الجلسة، أو بعد ٣ ساعات من الخمول، أو فور إعادة تشغيل الخادم.
> الدائم الوحيد — وباختيار المدرب — هو **حسابه وأسئلته المحفوظة**، وهي محتواه هو لا بيانات طلابه.
> ويبقى استخدام التطبيق بلا حساب متاحاً بالكامل.

### اللغة 🌐

التطبيق **ثنائي اللغة بالكامل** (عربي/إنجليزي): الصفحة الرئيسية، دخول المدرب، لوحة المعلّم،
المحرّر، مساعد الذكاء الاصطناعي، لوحة التحليلات، شاشة المشارك، شاشة البروجكتر، وتقارير
PDF/Excel. تُكتشف لغة المتصفح تلقائياً (عربي ⇄ عربي، أي شيء آخر ⇄ إنجليزي) مع زر تبديل يدوي
يحفظ الاختيار، واتجاه الصفحة (RTL/LTR) يتبدّل معها قبل أي رسم.

**لغة النشاط تتبع منشئه:** حين يطلق المعلّم نشاطاً تُحفظ لغته الحالية مع النشاط، فيرى كل مشارك
النشاط بلغة صاحبه مهما كانت لغة متصفحه — نشاط إنجليزي يظهر بالإنجليزية وLTR حتى على متصفح عربي،
والعكس. وهذا لا يغيّر تفضيل الطالب المحفوظ لبقية الموقع.

**لا شيء في التطبيق بالعربية وحدها بعد الآن** — بما في ذلك **دليل المعلّم** المطوّل.

## التشغيل

```bash
npm install
npm start          # http://localhost:3000
```

> **مهم:** التطبيق يحتاج خادم Node يعمل. فتح ملفات `public/*.html` مباشرة من المجلد (بروتوكول `file://`)
> أو من خادم ملفات ثابت لن ينجح: ستظهر الصفحات لكن إنشاء الجلسات والاتصال المباشر لن يعملا.
> في هذه الحالة يعرض التطبيق شريطاً تحذيرياً يشرح الحل بدل رسالة خطأ غامضة.
> القوالب الجاهزة تعمل دائماً لأنها محمّلة مع الصفحة بلا أي طلب شبكة.

للتطوير مع إعادة التحميل التلقائي:

```bash
npm run dev
```

الاختبارات (تكامل حقيقي عبر HTTP + WebSocket):

```bash
npm test
```

متغيرات البيئة: `PORT` (افتراضياً `3000`) — والتشغيل المحلي لا يحتاج غيره.
الجدول الكامل لمتغيرات الإنتاج (قاعدة البيانات، دخول جوجل، الذكاء الاصطناعي، المالك)
في [إعدادات Render](#٢-متغيرات-البيئة-الموصى-بها).

## النشر على الإنترنت

التطبيق يحتاج **عملية Node دائمة** لسببين: خادم WebSocket للاتصال المباشر، وحالة الجلسة في ذاكرة العملية.

### ✅ منصات تعمل (بلا أي تعديل)

| المنصة | الطريقة |
| --- | --- |
| **Render** | اربط المستودع — ملف `render.yaml` جاهز ([التفاصيل أدناه](#إعدادات-render-بالتفصيل)) |
| **Railway** | اربط المستودع؛ يكتشف `npm start` تلقائياً |
| **Fly.io** | `fly launch` ثم `fly deploy` — يستخدم `Dockerfile` الجاهز |
| **Koyeb / Cloud Run / VPS** | من `Dockerfile` مباشرة، أو `npm ci && npm start` خلف Nginx |

المنصة تحقن `PORT` تلقائياً والتطبيق يلتزم به. لا حاجة لأي قاعدة بيانات أو متغيرات أخرى.

### ❌ منصات لا تصلح

**Vercel · Netlify · GitHub Pages · Cloudflare Pages** (بوضعها الثابت/serverless):

- لا تستضيف خادم WebSocket، فالاتصال المباشر لن يعمل.
- الدوالّ serverless قصيرة العمر ولا تتشارك الذاكرة، فحالة الجلسة تضيع بين الطلبات.

النتيجة عليها: **تظهر الصفحات وتفشل كل طلبات `/api`** — القوالب تعمل (لأنها محمّلة مع الصفحة)
لكن إنشاء جلسة يفشل. التطبيق يكتشف هذه الحالة ويعرض شريطاً يشرح السبب بدل رسالة خطأ غامضة.

> لتشغيله على Vercel يلزم استبدال طبقة الاتصال المباشر بخدمة خارجية (Ably/Pusher) ونقل الحالة إلى مخزن
> خارجي مثل Redis — وهي إعادة بناء لجوهر التطبيق، لذلك التوصية هي استخدام إحدى المنصات أعلاه.

## إعدادات Render بالتفصيل

### ١. نوع الخدمة (الأهم)

اختر **Web Service** وليس Static Site. الفرق حاسم:
Static Site تخدم ملفات فقط، فتظهر صفحات التطبيق لكن كل `/api` يفشل ولا يعمل أي اتصال مباشر.

| الحقل | القيمة |
| --- | --- |
| Type | **Web Service** |
| Runtime | Node |
| Build Command | `npm ci` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |

لا تضبط `PORT` يدوياً — Render يحقنه والتطبيق يلتزم به.

### ٢. متغيرات البيئة

**لازمة للإنتاج:**

| المتغير | القيمة | لماذا هي لازمة |
| --- | --- | --- |
| `DATABASE_URL` | رابط Postgres | بدونها تُكتب الحسابات في ملف على قرص مؤقت فتضيع مع كل نشر. استخدم **session pooler** من Supabase لا العنوان المباشر `db.*.supabase.co` |
| `GOOGLE_CLIENT_ID` | من Google Cloud | بدونها **لا يعمل تسجيل الدخول إطلاقاً** — وهو وسيلة الدخول الوحيدة |
| `GOOGLE_CLIENT_SECRET` | من Google Cloud | كما سبق |
| `ADMIN_EMAILS` | بريدك | يحدّد صاحب لوحة المالك. له قيمة افتراضية في الكود، لكن ضبطه صراحةً يجعل الصلاحية ظاهرة في لوحة Render لا مدفونة في المصدر |

**اختيارية (لها قيم افتراضية آمنة):**

| المتغير | الافتراضي | الأثر |
| --- | --- | --- |
| `NODE_ENV` | — | `production` وضع الإنتاج (يكتم سجلّ الاختبارات فقط؛ التخزين المؤقت مضبوط في الكود لا به) |
| `NODE_VERSION` | افتراضي المنصة | مثبّت على `22` في `render.yaml` |
| `KEEP_ALIVE_MINUTES` | `10` | نبضة تمنع نوم الخدمة أثناء المحاضرة |
| `SESSION_IDLE_MINUTES` | `180` | مدة بقاء الجلسة بلا نشاط |
| `SESSION_ENDED_MINUTES` | `30` | مدة بقاء نتائج جلسة انتهت |
| `DATA_DIR` | `./data` | مجلد ملف التخزين حين لا توجد `DATABASE_URL` |
| `KEEP_ALIVE_URL` | `RENDER_EXTERNAL_URL` | عنوان النبضة إن لم تحقنه المنصة |
| `PREMIUM_WHATSAPP` | `970597034066` | رقم التواصل في نافذة الاشتراك |
| `PREMIUM_PRICE_USD` | `5` | السعر المعروض |

**للمساعد الذكي (اختياري — بدونها يردّ المساعد ٥٠٣ ويبقى باقي التطبيق سليماً):**

| المتغير | الافتراضي | الأثر |
| --- | --- | --- |
| `AZURE_OPENAI_KEY` | — | المفتاح. يُقبل كذلك الاسم البديل `AZURE_OPENAI_API_KEY` |
| `AZURE_OPENAI_ENDPOINT` | مورد makeflow | **اضبطه صراحةً** مع أي مفتاح جديد، وإلا ذهبت الطلبات إلى المورد الافتراضي |
| `AZURE_OPENAI_MODEL` | `gpt-4.1` | اسم النشر |
| `AZURE_OPENAI_API_VERSION` | — | لمسار قديم لا يستخدم `/openai/v1/` |

> **لا يوجد أي سرّ ذي قيمة افتراضية في الكود** — المفاتيح كلها تبدأ فارغة، والميزة التي ينقصها مفتاحها تتعطّل وحدها بلا أن تعمل بمفتاح خاطئ.

الاختيارية كلها موجودة في `render.yaml`، فإن ربطت المستودع كـ Blueprint تُضبط تلقائياً.
اللازمة تضبطها بنفسك في لوحة Render لأنها أسرار.

### ٣. مشكلة النوم بعد ١٥ دقيقة (وحلّها)

الخطة المجانية على Render **توقف الخدمة بعد ١٥ دقيقة بلا طلبات واردة**، وإيقافها يمسح
كل الجلسات لأن التخزين في الذاكرة. هذا يعني أن جلسة بدأتها في أول المحاضرة قد تختفي في وسطها.

**الحل المدمج:** الخادم يرسل لنفسه نبضة خفيفة كل ١٠ دقائق عبر عنوانه العام
(`RENDER_EXTERNAL_URL` الذي يضبطه Render تلقائياً) — **لكن فقط ما دامت هناك جلسة قائمة**،
حتى لا تُستهلك ساعات الخطة المجانية بلا داعٍ. فما دام لديك نشاط مفتوح، لن تنام الخدمة.

للتحقق من أنها مفعّلة، افتح `https://<موقعك>/api/health` وابحث عن:

```json
{ "ok": true, "config": { "keepAlive": "https://<موقعك>", "keepAliveMinutes": 10 } }
```

إن كانت `keepAlive` تساوي `null` فالنبضة معطّلة — أضف `KEEP_ALIVE_URL` بعنوان موقعك يدوياً.

> الخطة المجانية تمنح ٧٥٠ ساعة شهرياً. النبضة تعمل أثناء الجلسات فقط، لكن إن كنت تستخدم
> التطبيق يومياً وبكثافة ففكّر في أرخص خطة مدفوعة — فهي لا تنام أصلاً وتزول المشكلة تماماً.

### ٤. حلّ مشكلة «Not Found»

هذه الكلمة الإنجليزية **لا يُخرجها التطبيق إطلاقاً** — كل رسائله عربية، وأي مسار مجهول يعيد
الصفحة الرئيسية، ورابط الدخول `/j/<الرمز>` يحوّل دائماً إلى صفحة المشاركة. فإن رأيتها فهي من Render.

للتشخيص في ثانية واحدة:

```bash
curl -I https://<موقعك>/api/health
```

| ما تراه | المعنى | العلاج |
| --- | --- | --- |
| ترويسة `x-render-routing: no-server` | لا توجد خدمة تعمل على هذا العنوان | الخدمة موقوفة أو فشل نشرها أو نوعها Static Site |
| `404` وردّ HTML من Render | غالباً Static Site | أعد إنشاءها كـ Web Service |
| `200` مع `{"ok":true}` | الخادم يعمل | المشكلة في الجلسة نفسها لا في النشر |

وإذا كان الخادم يعمل لكن الرابط لا يفتح جلستك، فالسبب أن الجلسة نفسها اختفت: إما لأن الخدمة نامت
وأُعيد تشغيلها (راجع القسم أعلاه)، أو لأن نشراً جديداً أعاد تشغيل العملية. في هذه الحالة تظهر
للمتدرب رسالة عربية واضحة «لم نعثر على الجلسة» — أنشئ جلسة جديدة واعرض رمزها.

> **تذكّر:** رمز الجلسة صالح ما دامت العملية تعمل. أي إعادة نشر تمسح الجلسات القائمة —
> فلا تنشر تحديثاً أثناء محاضرة جارية.

### أنواع الأسئلة التسعة ونزاهة الاختبار 🔢

بعد `order` و`match` صارت الأنواع تسعة، ونوعان منها **يُصحَّحان آلياً بعلامة جزئية** — وهو ما
تفتقده أغلب المنصات: من رتّب ثلاثة من أربعة صحيحاً يأخذ ٧٥٪ لا صفراً.

| النوع | التصحيح | الفكرة |
| --- | --- | --- |
| 🔢 **رتّب** (`order`) | آلي، جزئي | المعلّم يكتب العناصر بالترتيب الصحيح، والتطبيق يخلطها لكل طالب. النسبة = كم عنصراً وقع في موضعه |
| 🔗 **طابِق** (`match`) | آلي، جزئي | أزواج (طرف ⟷ ما يقابله)؛ الأطراف اليمنى تُخلط وتصير قائمة اختيار لكل طرف أيسر. النسبة = كم زوجاً صحّ |

**واجهة الطالب بالنقر لا بالسحب**: السحب على الجوال هشّ — يتعارك مع تمرير الصفحة ومع قارئ
الشاشة. الترتيب بالنقر بالتسلسل (ونقرة ثانية تُلغي)، والمطابقة بقائمة اختيار. يعمل بإصبع واحدة
وبلوحة مفاتيح.

**نتائج البروجكتر** لهذين النوعين تعرض ما يفيد المعلّم فعلاً: متوسط الإتقان، وكم أتقنه كاملاً،
و**نسبة كل عنصر أو زوج على حدة** — فيعرف أي خطوة تحديداً تعثّر فيها الصف.

#### نزاهة الاختبار

| الإعداد | ما يفعل |
| --- | --- |
| **خلط ترتيب الأسئلة** | ترتيب مختلف في كل إطلاق، فلا يفيد أن يعرف طلاب الحصة التالية التسلسل |
| **خلط الخيارات لكل طالب** | ترتيب الخيارات يختلف من جهاز لآخر، فـ«ب» عند جارك ليست «ب» عندك |

الخلط **مبذور بمعرّف الطالب** لا عشوائياً في كل رسم: الطالب الذي يفقد الاتصال ويعود يرى الترتيب
نفسه، وإلا لأجاب على خيار غير الذي رآه.

### الهوية والتذييل والصفحات القانونية 🏢

تذييل موحّد في كل صفحة (`public/assets/js/footer.js`) — مكان واحد بدل تكراره في ست ملفات:
هوية **makeflow** ورابطها، وواتساب الدعم والشكاوى، وروابط **سياسة الخصوصية** و**شروط الاستخدام**،
وزرّ تثبيت التطبيق. لا يظهر على شاشة الطالب ولا البروجكتر عمداً (تشويش أثناء الحصة).

الصفحتان القانونيتان (`privacy.html` و`terms.html`) محتواهما بيانات ثنائية اللغة في
`assets/js/legal.js`، ومكتوبتان لتصفا ما يفعله التطبيق فعلاً: نتائج الطلاب لا تُحفظ، ولا متتبّعات،
ولا بيع بيانات. **أي تغيير في سلوك التطبيق يجب أن ينعكس فيهما.**

### تثبيت التطبيق على الجوال 📲

زر التثبيت في التذييل يظهر **فقط حين يعرض المتصفح إمكانية التثبيت فعلاً** — لا نَعِد بما لا نملك.
ولكي يعرضها المتصفح لزم شيئان كانا ناقصين:

- **عامل خدمة** (`sw.js`): كروم لا يُطلق `beforeinstallprompt` بلا عامل خدمة يعالج `fetch`.
  عاملُنا **لا يخزّن أي ملف من التطبيق** عمداً — الحالة في ذاكرة الخادم، وأي نسخة مخبّأة قديمة
  تعني معلّماً يرى واجهة لا تطابق خادمها بعد النشر. يمرّر كل طلب إلى الشبكة، ويحتفظ فقط
  بصفحة اعتذار (`offline.html`) تُعرض حين ينقطع الاتصال.
- **أيقونات PNG** بمقاسي 192 و512 (ومنها maskable لأندرويد) في المانيفست.

على iOS لا يوجد `beforeinstallprompt` إطلاقاً، فيشرح الزر خطوة «إضافة إلى الشاشة الرئيسية» بدل
أن يكون زراً لا يفعل شيئاً.

### الأوسمة والترتيب: النشاط المُقيَّم وحده 🏅

`Session.isAssessed` تحسم: نشاطٌ فيه سؤال مصحَّح آلياً أو سؤال يدوي بعلامة، وإعداد النقاط ليس
«بلا نقاط». وما عداه — استطلاع الرأي وسحابة الكلمات والمقياس — **لا أوسمة فيه ولا ترتيب**:
فالمستطلَع يُشكَر لا يُقيَّم، ووسام «الأسرع» أو مركزٌ بين المشاركين يوحيان بتفوّق في نشاط لا فائز فيه.
مغطّى بخمسة اختبارات في `test/badges.test.js`.

### كم صفاً يتحمّل الخادم؟ (مقيس لا مُقدَّر) 📊

قِسنا الحِمل على خادم مقيّد بـ**0.1 معالج** — حصة خطة Render المجانية بالضبط — عبر مجموعة
تحكّم (cgroup)، والعملاء من خارج القيد:

| الصفوف المتزامنة | الطلاب | المقابس | زمن انضمام الجميع | زمن استجابة الطالب (p95) | ذاكرة |
| --- | --- | --- | --- | --- | --- |
| ١٠ | ٢٥٠ | ٢٧٠ | ٢٫٢ ث | ٥١ms | ٨٩MB |
| ١٥ | ٣٧٥ | ٤٠٥ | ٣٫٥ ث | ٥١ms | ٩٢MB |
| ٢٥ | ٦٢٥ | ٦٧٥ | ٥٫١ ث | ٥٢ms | ١١٢MB |
| ٤٠ | ١٠٠٠ | ١٠٨٠ | ٧٫٧ ث | ٥١ms | — |

**بلا فقدان إجابة واحدة** في أي مستوى، وبلا أي تسرّب بين الصفوف: لا مشارك يظهر في صفٍّ غير صفّه،
ولا لوحة معلّم تعرض طلاب غيره، ونقاط كل طالب صحيحة إلى آخر نقطة (بما فيها مضاعف السلسلة).

الشيء الوحيد الذي يتأثّر بالحمل هو **لحظة الانضمام الجماعي** (مصافحة المقابس)، وحتى عند ألف طالب
يدخلون في اللحظة نفسها لا تتجاوز ثماني ثوانٍ. أما زمن استجابة الإجابة فثابت لا يكاد يتغيّر.

الذاكرة: الخطة المجانية ٥١٢MB، والاستهلاك يبقى تحت ١٢٠MB حتى عند ٦٢٥ طالباً. وحدّ جسم الطلب
يمنع أي نشاط واحد من تجاوز ١٢MB مهما بلغت صوره.

### الإغلاق المرتّب عند النشر 🔌

`server.close()` وحده **لا يكفي**: فهو ينتظر كل اتصال مفتوح، ومقابس الويب مفتوحة عمداً طوال
الحصة. فما دام مدرب أو بروجكتر أو طالب متصلاً، لا يُستدعى ردّ الإغلاق أبداً، وتقتل المنصة
العمليةَ قسراً بعد مهلتها — فيرى الصفّ انقطاعاً غامضاً.

لذلك يغلق الخادم مقابس الويب أولاً برمز **1001** («الخادم يُغلق») كي يعرف عميلُ كل طالب أن
يُعيد الاتصال، ثم يُغلق الخادم، ومعه مهلة خمس ثوانٍ تضمن الخروج مهما تعثّر اتصال.

هذا السلوك مغطّى بثلاثة اختبارات في `test/shutdown.test.js`، أحدها يُثبت أن المعالج القديم
يعلق فعلاً — فإن صار الخروج تلقائياً في نسخة عقدة قادمة، سيُنبّهك ذلك الاختبار بالفشل.

## كيف يعمل؟

### للمدرب
1. افتح `/host.html` → ابنِ النشاط (أو ابدأ من قالب جاهز).
2. اضغط **ابدأ الجلسة** → يظهر رمز QR + رمز من ٦ أرقام.
3. تحكّم بالعرض: إغلاق الإجابة، كشف النتائج، لوحة الترتيب، السؤال التالي.
4. تابع **لوحة التحكم**: نسبة التفاعل، دقة كل سؤال، تقدّم كل مشارك، متوسط زمن الإجابة.
5. عند الانتهاء يمكنك **تنزيل النتائج** كملف JSON إن أردت الاحتفاظ بها (الخادم لا يحفظ شيئاً).

> مفتاح المضيف (`hostToken`) يُحفظ في `localStorage` على متصفح المدرب فقط. من يملكه يتحكم بالجلسة — لذلك لا يمكن استئناف جلسة من جهاز آخر.

### من ينقل إلى السؤال التالي؟ (يُختار عند الإنشاء)

| الوضع | ماذا يحدث | متى تستخدمه |
| --- | --- | --- |
| 🎛️ **المدرب** | أنت تنقل الشرائح وتتحكم بالإيقاع (الافتراضي) | الشرح والمناقشة بين الأسئلة |
| ⏱️ **تلقائي** | الجميع معاً، وينتقل وحده بعد عرض النتائج بمدة تحدّدها (٣–١٥ ثانية) | مسابقة سريعة بلا توقف |
| 🏃 **حر** | كل متدرب يتقدّم بسرعته: يجيب، يرى نتيجته، ويضغط «التالي» | واجب فردي أو استبيان أو صفوف كبيرة |

في الوضع الحر يرى المدرب لوحة مباشرة: أين وصل كل متدرب (`٢/٣`)، من أنهى، ونتائج أي سؤال بالتصفّح بينها.
ولكل متدرب مؤقّته الخاص يبدأ لحظة فتحه للسؤال، وإن انتهى وقته يتابع إلى التالي بلا عقوبة.

**البدء التلقائي 🚀** (مفعّل افتراضياً في الوضع الحر): ينطلق المتدرب بمجرد دخوله — **لا ينتظر المدرب
إطلاقاً**، لا في البدء ولا في الانتقال. أطفئ الخيار إن أردت أن يبقى الجميع في القاعة حتى تضغط «بدء».

### نظام النقاط والتحفيز

**احتساب النقاط** (يُختار عند الإنشاء):

| الوضع | القاعدة |
| --- | --- |
| ⚡ **بالسرعة** | كاملة للإجابة الفورية وتتناقص حتى نصف القيمة عند آخر ثانية (الافتراضي) |
| 🎯 **ثابتة** | نفس النقاط لكل إجابة صحيحة مهما كانت السرعة — أعدل للمتدربين البطيئين في القراءة |
| 🕊️ **بلا نقاط** | تعلّم بلا منافسة: تختفي النقاط والترتيب تماماً |

**علامة كل سؤال:** يضع المدرب العلامة التي يريدها لكل سؤال بحرية (٠ إلى ١٠٠٠٠)، مع أزرار سريعة للقيم الشائعة.
سؤال بعلامة ٠ يبقى في النشاط لكنه بلا رصيد.

**شرح الإجابة الصحيحة 💡** (اختياري): لكل سؤال حقل شرح، وعند تفعيل «إظهار الإجابة الصحيحة» في إعدادات
النشاط يرى المتدرب — بعد إجابته فقط — الإجابة الصحيحة وسببها. الشرح **لا يُرسل إلى المتصفح إطلاقاً** قبل
أن يجيب، فلا يمكن استخراجه مسبقاً. وإن أطفأ المدرب الخيار فلا يُكشف شيء قبل عرض النتائج للجميع.

**مضاعف السلاسل 🔥** (اختياري): كل إجابة صحيحة متتالية تزيد النقاط ١٠٪ حتى سقف ٥٠٪ —
فالمتدرب الذي يجيب ٤ صحيحات متتالية يأخذ ×1.3 على الرابعة. يظهر المضاعف للمتدرب فور إجابته.

**الأوسمة 🏅** تُحسب في النهاية من الأداء الفعلي، وتمنح كل متدرب سبباً للفخر لا يلتقطه الترتيب وحده:

| الوسام | يستحقه |
| --- | --- |
| 🎯 دقة كاملة | أجاب على سؤالين مصحّحين فأكثر وكلها صحيحة |
| ⚡ الأسرع إجابةً | أقل متوسط زمن بين من أجابوا على نصف الأسئلة فأكثر |
| 🔥 أطول سلسلة | صاحب أطول سلسلة صحيحة (٣ فأكثر) |
| 💪 أجاب على كل الأسئلة | لم يفوّت سؤالاً واحداً |
| 🚀 أسرع من بدأ | الأكثر سبقاً إلى الإجابة قبل الجميع |

**الصعود والهبوط:** بين الأسئلة يرى المتدرب «⬆ صعدت ٣ مراكز» أو «⬇ نزلت مركزاً».

### التنقّل

- **المتدرب:** زر 🚪 للخروج من النشاط (بتأكيد أثناء الجلسة)، ثم يعود للصفحة الرئيسية.
- **المدرب:** زر 🏠 للصفحة الرئيسية — مغادرة الصفحة **لا تُنهي الجلسة**، وتستطيع استئنافها من
  «استئناف جلستي السابقة». وفي شاشة النهاية أزرار «نشاط جديد» و«الصفحة الرئيسية».
- إنهاء الجلسة أو حذفها يبقى قراراً صريحاً من المدرب (زر الإنهاء 🏁 أو الحذف 🗑).

### شاشة عرض منفصلة للبروجكتر 🖥️

في تبويب «🔗 المشاركة» زر **«افتح شاشة العرض»** يفتح رابطاً بلا أي زر تحكم — مناسب للبروجكتر
أو التلفاز، بينما تتحكم أنت من جوالك. تعرض القاعة (QR والرمز)، السؤال والمؤقّت، النتائج (أعمدة/سحابة
كلمات/مقياس)، ومنصة التتويج، بخط كبير يُرى من بعيد. الأمان بنفس مفتاح المضيف — من يملك الرابط فقط يراها.

### وضع الفرق 🏳️

فعّله في إعدادات النشاط واختر عدد الفرق (٢-٨). كل مشارك يُوزَّع تلقائياً على فريق ملوّن عند الانضمام
(بتوازن مستمر — أصغر فريق عدداً يستقبل التالي)، ونقاط الفريق مجموع نقاط أعضائه. يظهر ترتيب الفرق
بجانب الترتيب الفردي في لوحتي المدرب والمشارك وشاشة العرض. يناسب الصفوف الكبيرة.

### حساب المدرب ونشاطاته المحفوظة 🔐

الحساب اختياري تماماً — كل شيء يعمل بدونه، لكنه يحفظ أنشطتك لتعيد استخدامها.

1. **دخول عبر جوجل فقط** من `/login.html` — بلا كلمات مرور وبلا نموذج تسجيل منفصل.
   بريد جوجل مُتحقَّق منه دائماً من طرف جوجل، فيصعب على شخص واحد فتح عدة حسابات كما كان
   ممكناً ببريد وهمي + كلمة مرور: **شخص واحد = حساب واحد** عملياً.
2. **الحفظ تلقائي**: أي نشاط تطلقه وأنت مسجّل الدخول يُحفظ في حسابك فوراً — لا يحتاج زر حفظ،
   وإعادة إطلاق نفس النشاط تحدّثه بدل تكديس نسخ. (زر «💾 حفظ في حسابي» ما زال موجوداً للحفظ دون إطلاق.)
3. **إنهاء الجلسة أو إيقافها لا يحذف النشاط** — يبقى في حسابك جاهزاً لإعادة الإطلاق متى شئت.
4. صفحة **«📚 نشاطاتي»** (`/host.html#/mine`) تعرض كل أنشطتك مع عدد الأسئلة ووضع التقدّم وتاريخ آخر تعديل، ولكل نشاط:
   - **🚀 إطلاق جلسة** — يفتح جلسة مباشرة جديدة برمز QR.
   - **✏️ فتح وتعديل** — يحمّله في المحرّر.
   - **📄 استنساخ** — نسخة مستقلة تعدّلها دون المساس بالأصل.
   - **🗑 حذف** — نهائياً بعد تأكيد.
   - إن كان له جلسة تعمل الآن تظهر شارة **«مباشر»** مع زر **«↩ العودة للجلسة»**.
5. **📚 بنك الأسئلة**: على أي سؤال في المحرّر زر «📚 احفظ في البنك» يحفظه مستقلاً عن أي نشاط.
   وفي قسم «٤. الأسئلة» بطاقة تعرض بنكك مع زر **«➕ أضف»** لإدراج أي سؤال محفوظ في النشاط الحالي
   بضغطة، وزر حذف. يوفّر إعادة كتابة الأسئلة المتكرّرة بين الأنشطة.

**الأمان:** لا كلمات مرور مخزَّنة إطلاقاً — الهوية تُثبَت عبر تدفّق OAuth القياسي مع جوجل
(Authorization Code) بحماية CSRF عبر معامل `state` في كوكي قصير العمر. جلسة الدخول عبر كوكي
`HttpOnly` + `SameSite=Lax` (و`Secure` على https). ولا يستطيع مدرب رؤية أنشطة غيره أو تعديلها
أو إطلاقها — الملكية مفحوصة على الخادم في كل مسار.

**المحفوظ:** البريد والاسم من جوجل، وعنوان النشاط وإعداداته وأسئلته. **غير المحفوظ:** أي كلمة مرور،
وأسماء الطلاب، وإجاباتهم، ونقاطهم، وأي نتيجة.

#### تفعيل الدخول عبر جوجل

1. **Google Cloud Console** ← أنشئ مشروعاً (أو استخدم موجوداً) ← **APIs & Services ← OAuth consent screen**:
   اختر **External**، واملأ اسم التطبيق وبريد الدعم — لا حاجة لمراجعة جوجل لعدد مستخدمين صغير (Testing/غير منشور يكفي مبدئياً، أو انشره لاحقاً لإزالة حد الـ 100 مستخدم).
2. **APIs & Services ← Credentials ← Create Credentials ← OAuth client ID** ← النوع **Web application**.
3. تحت **Authorized redirect URIs** أضف رابط النطاق الذي تنشر عليه، بالضبط:
   ```
   https://<نطاقك>/api/auth/google/callback
   ```
   أضف صفاً لكل نطاق تستخدمه فعلياً (رابط Render، ونطاقك المخصّص إن أضفته لاحقاً، و`http://localhost:3000/api/auth/google/callback` للتطوير المحلي إن رغبت).
4. انسخ **Client ID** و**Client secret**، وضعهما متغيّرَي بيئة على الخادم:
   ```
   GOOGLE_CLIENT_ID=...
   GOOGLE_CLIENT_SECRET=...
   ```
5. أعد النشر. تحقّق من `/api/health` — يجب أن ترى `"googleLoginConfigured": true`.

بلا هذين المتغيّرين يبقى التطبيق يعمل بالكامل (الجلسات الحية، الأسئلة، كل شيء) — فقط صفحة
الدخول تُظهر تنبيهاً بأن الحساب غير مُفعّل بعد بدل زر معطّل.

#### تفعيل «صمّم نشاطك بالذكاء الاصطناعي»

المدرب يحاور المساعد في `#/ai`، يفهم منه ما يريد، يصوغ الأسئلة ويعرضها، وعند
الموافقة تُفتح المسودة في المحرّر جاهزة. النموذج يعمل عبر **Azure OpenAI**.

> ⚠️ **المفتاح لا يُكتب في المستودع إطلاقاً.** أضفه متغيّر بيئة على الاستضافة فقط،
> والمتصفح لا يراه لأن كل نداء يمرّ عبر خادمنا (`/api/ai/design`).

| المتغيّر | إلزامي | القيمة |
| --- | --- | --- |
| `AZURE_OPENAI_KEY` | نعم | مفتاح المورد من بوابة أزور |
| `AZURE_OPENAI_ENDPOINT` | لا | افتراضياً نقطة مشروع `makeflow-ai` (واجهة Responses) |
| `AZURE_OPENAI_MODEL` | لا | افتراضياً `gpt-4.1` |
| `AZURE_OPENAI_API_VERSION` | لا | تُضاف فقط لنقاط النشر القديمة `/openai/deployments/...` |

بعد إضافة المفتاح وإعادة النشر تحقّق من `/api/health` — يجب أن ترى `"aiConfigured": true`.
بلا المفتاح يبقى كل شيء يعمل، وتظهر في صفحة المساعد ملاحظة بأنه غير مُفعّل.

الحدود المدمجة: المساعد للمدربين المسجّلين فقط، وبحدّ ٦٠ رسالة لكل مدرب في الساعة،
وبحدّ ٤٠ سؤالاً في المسودة الواحدة.

#### اللغتان: عربي/إنجليزي 🌐

الكشف تلقائي حسب لغة متصفح المستخدم، مع زر تبديل يدوي (EN/AR) يحفظ الاختيار، واتجاه الصفحة
(rtl/ltr) يُضبط قبل أي رسم فلا تظهر ومضة اتجاه خاطئ.

**مترجَم بالكامل:** الصفحة الرئيسية (الدخول بالرمز) · صفحة دخول المدرب · **شاشة المشارك** (كل رحلة
الطالب: الانضمام، الأسئلة بأنواعها السبعة، التغذية الراجعة، الترتيب، بطاقة النتيجة) · **شاشة
البروجكتر** · **لوحة المعلّم** (البثّ المباشر، التصحيح اليدوي، الجدولة، أنشطتي، بنك الأسئلة، لوحة
المالك) · **المحرّر** بكل أنواع الأسئلة والقوالب · **مساعد الذكاء الاصطناعي** · **لوحة التحليلات**
والتوصيات · **تقارير PDF وملفات Excel** (بما فيها اتجاه الصفحة وأسماء الأوراق).

القاموس ٧٦٤ مفتاحاً لكل لغة، وتُتحقّق المطابقة بينهما آلياً.

**لغة النشاط:** عند الإطلاق تُخزَّن لغة المعلّم في `settings.lang`، وصفحتا الطالب والبروجكتر
تستدعيان `I18n.setLang(lang, { remember: false })` قبل أول رسم — فتتبعان لغة النشاط دون المساس
بتفضيل الزائر المحفوظ. الأنشطة المُنشأة عبر الـAPI بلا لغة صريحة تبقى على الكشف التلقائي.

**دليل المعلّم** ثنائي اللغة أيضاً: محتواه بيانات مهيكلة في `public/assets/js/help.js`
(الأقسام التسعة بلغتيهما)، تُرسم منها الصفحة كاملة وتُعاد رسمها فوراً عند تبديل اللغة.

#### جدولة الاختبار ومدّته ⏰

في إعدادات النشاط: **موعد فتح الاختبار** (تاريخ وساعة) و**مدة الاختبار بالدقائق**.

- الجلسة تبقى في القاعة حتى الموعد، ويرى الطلاب وشاشة البروجكتر **عدّاداً تنازلياً**، ثم **تبدأ وحدها** بلا أي أمر من المدرب.
- عند انتهاء المدة **يُقفل الاختبار تلقائياً** للجميع وتظهر النتائج، ويظهر أثناءه شريط «ينتهي الاختبار خلال …» للطالب والمعلّم.
- البدء اليدوي المبكر يُلغي مؤقّت الفتح، وتُحسب المدة من لحظة البدء الفعلي.
- الجلسة المجدولة **لا يمسحها منظّف الجلسات** قبل موعدها، فيمكن إطلاقها قبل أيام وتوزيع رمزها.
- الحدود: الموعد حتى ٩٠ يوماً، والمدة حتى ٧٢٠ دقيقة (١٢ ساعة). موعد في الماضي يُعامَل كأنه بلا جدولة.

#### تحليل النتائج والتقارير 📈

بعد أي نشاط (وأثناءه) يفتح المعلّم تبويب **«📈 التحليل»** في لوحة الجلسة فيرى:

- **أرقام سريعة**: عدد الطلاب والأسئلة، مدة النشاط، متوسط الصف، الوسيط، نسبة المشاركة.
- **رسوم** (SVG/CSS بلا أي مكتبة خارجية): حلقة متوسط الدرجات، توزيع الدرجات على خمس شرائح،
  دقة الإجابة لكل سؤال، ومتوسط زمن الإجابة لكل سؤال.
- **بطاقات مميّزة**: 🔴 أصعب سؤال · 🟢 أسهل سؤال · ⚡ الأسرع إجابةً · 🐢 الأبطأ · ⏭ الأكثر تخطّياً.
- **جدول الطلاب**: الدرجة والنسبة والترتيب وعدد الصحيح ومتوسط الزمن.
- **توصيات مكتوبة** مبنية على أرقام هذا النشاط تحديداً (لا نصائح عامة): ماذا يعيد شرحه،
  أي سؤال صياغته ملتبسة، من يحتاج متابعة فردية، وهل الوقت كان كافياً.

**الملفات نوعان** (بريميوم)، لكلٍّ جمهوره:

- **سجل علامات الطلاب** — من قسم *تقدم المشاركين* في لوحة التحكم: بطاقة النشاط وجدول العلامات
  مرتباً فقط، بلا أي تحليل. PDF الرسمي فيه سطرا **توقيع للمعلّم والمدير** — تقرير يُقدَّم للإدارة
  أو يُحفظ مرجعاً للعلامات. (`tapio-<الرمز>-results.pdf/.xlsx`)
- **تقرير التحليل الكامل** — من تبويب *التحليل* فقط: بطاقة النشاط، ملخّص التحليل وأبرز الأسئلة،
  رسم توزيع الدرجات، التوصيات، تفصيل كل سؤال، ثم سجل العلامات. Excel التحليل أربع أوراق:
  *بطاقة النشاط*، *الطلاب*، *الأسئلة*، *الإجابات* (كل إجابة في سطر). (`tapio-<الرمز>-report.pdf` و`tapio-<الرمز>.xlsx`)

**لكل تقرير زرّان، لأن للمعلّمين حاجتين مختلفتين:**

| الزر | ما يفعل | متى تستخدمه |
| --- | --- | --- |
| **📄 PDF ملوّن** | يفتح صفحة تقرير كاملة الأنماط ثم نافذة الطباعة؛ تختار «حفظ كـ PDF» | حين يهمّك الشكل: رسوم ملوّنة، دائرة نسبة، أشرطة، بطاقات توصيات |
| **⤓ ملف** | ينزّل ملف PDF فوراً بلا أي نافذة | حين تريد الملف بسرعة، أو تصدّر عشرات التقارير تباعاً |

التقرير الملوّن يستخدم **محرّك الرسوم نفسه** الذي يراه المعلّم في تبويب التحليل (SVG ونصّ حقيقي)،
فيخرج PDF متجهاً: نصّه قابل للتحديد والبحث، ورسومه حادّة عند أي تكبير.

> **مهم:** المتصفحات تحذف ألوان الخلفيات عند الطباعة افتراضاً، فكانت الأشرطة وبطاقات التوصيات
> تخرج بيضاء. يفرض التقرير `print-color-adjust: exact` فتُطبع بألوانها الحقيقية.

أما زرّ **⤓ ملف** فيبني الـPDF في المتصفح عبر jsPDF + autoTable وخط **Amiri** المضمّن
(`public/assets/vendor/`، رخصة SIL OFL) بلا أي اتصال خارجي — جداول مرتّبة بلا رسوم ملوّنة.
تُحمَّل مكتباته كسولاً عند أول ضغطة كي لا تثقل تحميل الصفحة.

#### دليل المعلّم 📖

صفحة `/help.html` (رابطها في الشريط العلوي وفي الصفحة الرئيسية): خطوات أول نشاط، جدول أنواع
الأسئلة ومتى تستخدم كلاً منها، **شرح احتساب النقاط بالتفصيل**، التصحيح اليدوي، أنماط العرض،
قراءة النتائج والتحليل، أفضل الممارسات (تصميم الأسئلة، الوقت، إدارة الصف، ما بعد النشاط)، وأسئلة شائعة.

#### التصحيح اليدوي 📝 (إجابة مفتوحة + أكمل الفراغ)

في المحرّر اختر **«إجابة مفتوحة»** أو **«أكمل الفراغ»** ثم اضبط **علامة السؤال** (٥ مثلاً):

- الطالب يكتب جوابه نصّاً، وتصله رسالة **«وصلت إجابتك — بانتظار تصحيح المدرب»** بلا أي نتيجة.
- في **لوحة التحكم** تظهر للمدرب بطاقة تصحيح لكل سؤال: نص كل إجابة أمامها أزرار العلامات
  من `0` إلى العلامة القصوى (وحقل رقمي إن تجاوزت ١٠) — فيمنح علامة كاملة أو **جزئية (٣ من ٥)** أو صفراً.
- بمجرد الضغط تظهر العلامة للطالب فوراً، وتُضاف إلى مجموعه وترتيبه. وتعديل العلامة لاحقاً يصحّح المجموع تلقائياً.
- **النتيجة النهائية محجوبة**: لو انتهى النشاط وبقيت له إجابة بلا تصحيح يرى «المدرب يصحّح إجابتك الآن»،
  ولا تظهر نقاطه ولا بطاقة نتيجته إلا بعد انتهاء التصحيح.
- العلامة صفر تُبقي السؤال سؤال رأي حرّ كما كان (بلا تصحيح ولا نقاط).

#### أكمل الفراغ ✏️

نوع سؤال جديد: تكتب الجملة وتضع `___` (ثلاث شرطات سفلية) مكان كل فراغ — حتى ٨ فراغات.

- **العلامة تتبع عدد الفراغات تلقائياً** (فراغان ⇐ علامتان) حتى تضبطها بنفسك.
- تستطيع كتابة **الإجابة المتوقعة** لكل فراغ: تظهر لك وحدك في لوحة التصحيح للمقارنة، ولا تصل الطالب.
- الطالب يرى الجملة نفسها وفيها حقول صغيرة يكتب فيها.
- التصحيح **يدوي دائماً** مثل السؤال النصّي: صح / خطأ / علامة جزئية.

#### صورة داخل السؤال 🖼 (بريميوم)

رفع الصور **ميزة بريميوم**: المشترك يرى زر رفع حقيقياً في كل سؤال، وغير المشترك يرى زراً مقفلاً
يشرح الاشتراك عند الضغط. والخادم يرفض إنشاء أو حفظ نشاط فيه صورة من حساب مجاني (٤٠٢) بدل حذفها صامتاً.

الصورة تُصغَّر داخل المتصفح (أقصى ضلع ١٢٨٠ بكسل، وحتى ٦٠٠ كيلوبايت)
قبل حفظها مع السؤال، وتظهر فوق نصّه عند الطالب وعلى شاشة البروجكتور وفي لوحة المدرب.
الصورة تُقدَّم للمشاركين كملف عبر `/api/sessions/:code/questions/:qid/image` (لا كنص داخل كل رسالة)
فتصل مرة واحدة ويخزّنها متصفح كل طالب. لا تُقبل إلا صور مرفوعة (data URL) — لا روابط خارجية.

#### اشتراك بريميوم ولوحة المالك

الميزات المدفوعة: **تصميم النشاط بالذكاء الاصطناعي** و**تصدير النتائج Excel و PDF**.
الاشتراك يدوي: المدرب يتواصل عبر واتساب، والمالك يفعّل حسابه من لوحة المالك.

| المتغيّر | الافتراضي | الوصف |
| --- | --- | --- |
| `ADMIN_EMAILS` | `jihad@makeflow.tech` | بريد المالك (أو عدّة بُرد مفصولة بفاصلة) — من يرى `#/admin` |
| `PREMIUM_WHATSAPP` | `970597034066` | الرقم الظاهر في بطاقة الاشتراك |
| `PREMIUM_PRICE_USD` | `5` | السعر الشهري المعروض |

**لوحة المالك** على `/host.html#/admin` (يظهر زرها 👑 في الشريط العلوي للمالك فقط):
تعرض كل المدربين — الاسم، البريد، تاريخ التسجيل، تاريخ انتهاء البريميوم — مع
أزرار «+ شهر / + سنة / − شهر / 📅 تاريخ محدّد / ✕ إلغاء». التمديد يبدأ من تاريخ
الانتهاء الحالي إن كان سارياً، وإلا من اليوم. المالك مشترك دائماً بلا أن يمنح نفسه شيئاً.

التاريخ محفوظ في عمود `premium_until` في جدول `users` — يُضاف تلقائياً عند أول تشغيل بعد التحديث.

> **حدود التطبيق الحالي:** بوابة المساعد الذكي على الخادم (لا يمكن تجاوزها)، أما
> أزرار التصدير فتُخفى في الواجهة والبيانات نفسها تبقى متاحة لمن يملك مفتاح المضيف
> عبر `/api/sessions/:code/export` (تنزيل JSON المجاني كما كان قبل البريميوم).

#### الربط بـ Supabase (موصى به ومجرَّب) 🟢

Supabase هي Postgres، فالتطبيق يعمل معها **بلا أي تعديل في الكود** — يكفي `DATABASE_URL`.

1. من لوحة Supabase: **Project Settings ← Database ← Connection string**.
2. اختر تبويب **Session pooler** ⚠️ ولا تختر «Direct connection».
3. انسخ الرابط، واستبدل `[YOUR-PASSWORD]` بكلمة مرور قاعدة البيانات.
4. ضعه في متغيّر البيئة `DATABASE_URL` على Render (أو أي منصة).

الجداول (`users`, `activities`, `auth_sessions`) تُنشأ تلقائياً عند أول تشغيل.

> **لماذا Session pooler تحديداً؟** الاتصال المباشر (`db.<ref>.supabase.co`) صار **IPv6 فقط**،
> و Render لا يوفّر IPv6 صادراً — فيفشل الاتصال. الـ Pooler يعمل على IPv4
> (`aws-0-<region>.pooler.supabase.com`). التطبيق يكتشف هذا الخطأ تحديداً ويطبع الحل.
>
> وإن كانت كلمة المرور تحوي رموزاً خاصة فرمِّزها في الرابط (`@` تصبح `%40`).

**للتأكد بعد النشر** افتح `/api/health` وابحث عن:

```json
{ "storage": { "kind": "postgres", "durable": true, "error": null } }
```

لو ظهر `"kind": "file"` فحقل `error` يشرح السبب بالضبط. التطبيق **لا يتوقف** عند فشل قاعدة البيانات —
تبقى الجلسات الحية تعمل، ويتحول تخزين الحسابات إلى ملف مؤقت مع تحذير ظاهر في «نشاطاتي».

مشروع هذا التطبيق على Supabase: **`tafa3l`** (المعرّف `vymuzlxguhwpjxrictac`، منطقة `eu-central-1`)
وجداوله الثلاثة مُنشأة مسبقاً، ومُفعّل عليها RLS بلا سياسات — فلا تُقرأ عبر واجهة Supabase العامة،
والتطبيق يصل إليها باتصال Postgres مباشر لا عبر PostgREST.

**لاختبار الربط قبل النشر** من جهازك:

```bash
DATABASE_URL='postgres://...pooler.supabase.com:5432/postgres' npm run test:pg
```

يشغّل ١٥ اختباراً على قاعدتك الفعلية: البقاء بعد إعادة التشغيل، عزل الملكية، والحسابات كاملة.

#### التخزين الدائم عند النشر

| الإعداد | السلوك |
| --- | --- |
| بلا `DATABASE_URL` | ملف JSON تحت `DATA_DIR` (افتراضياً `./data`) — مناسب للتطوير المحلي وللخوادم ذات قرص دائم |
| مع `DATABASE_URL` | Postgres (تُنشأ الجداول تلقائياً) — **الخيار الصحيح للنشر** |

> على استضافة بقرص مؤقت (مثل خطة Render المجانية) يضيع ملف JSON مع كل نشر. لذلك يعرض التطبيق
> تحذيراً في «نشاطاتي» ويكشف الحالة في `/api/health`. اضبط `DATABASE_URL` لقاعدة Postgres
> (Render Postgres أو Supabase أو Neon) لتبقى الحسابات والأنشطة.

### توليد الأسئلة بالذكاء الاصطناعي ⚡

توليد الأسئلة كله عبر **«صمّم بالذكاء الاصطناعي»** المدمج (تبويب المساعد في لوحة المدرب):
حاوره عن درسك فيصوغ النشاط ويعرضه عليك، وعند موافقتك يفتح في المحرّر جاهزاً.
(بطاقة «حوّل JSON إلى نشاط» القديمة أُزيلت من المحرّر — المساعد المدمج يغني عنها. محلّل JSON
المتسامح `Builder.parseImport` باقٍ داخلياً وهو الذي يفهم مخرجات المساعد نفسه.)

### المتعة والتفاعل
- **عدّاد «استعد ٣٢١»** متزامن على كل الشاشات قبل الأسئلة المؤقتة.
- **تفاعلات فورية:** يرسل المتدرب 👏 🔥 😂 😮 ❤️ 🤔 فتطير على شاشة العرض (بلا نسبتها لأحد، مع حدّ لمنع الإغراق).
- **أصوات** خفيفة مولّدة برمجياً (بلا ملفات) للدخول والتصحيح والعدّ التنازلي، مع زر كتم 🔇.
- **قصاصات ورق** عند الإجابة الصحيحة وعند ختام النشاط، و**منصة تتويج** للأوائل الثلاثة.
- **سلاسل الإجابات** 🔥 وشدّ في الثواني الخمس الأخيرة (نبض صوتي ولون تحذيري).
- **تجربة سريعة بضغطة واحدة** من الصفحة الرئيسية لتجريب كل شيء دون تجهيز أسئلة.

> كل المؤثرات تحترم `prefers-reduced-motion`، والصوت مطفأ يبقى مطفأ بين الجلسات.

### للمشارك
1. يمسح رمز QR أو يدخل الرمز في الصفحة الرئيسية.
2. **وضع الاسم:** يكتب اسمه أو كنيته ويحصل على أفاتار SVG عشوائي (يمكنه تغييره بزر النرد).
3. **الوضع المجهول:** إن أطفأ المدرب خيار «طلب الاسم»، يدخل مباشرة بلا اسم ولا تُنسب إجابته لأحد.
4. يجيب، فيرى نتيجته فوراً (صح/خطأ + النقاط) ثم النتائج المجمّعة.

إن انقطع الاتصال يُعاد الوصل تلقائياً وتُستعاد الحالة والنقاط عبر `sessionStorage`.

## واجهة REST

| الطريقة | المسار | الوصف |
| --- | --- | --- |
| `POST` | `/api/sessions` | إنشاء جلسة ← `{ code, hostToken, joinUrl }` |
| `GET` | `/api/sessions/:code` | معلومات عامة (للتحقق من الرمز قبل الدخول) |
| `PUT` | `/api/sessions/:code` | تعديل الأسئلة قبل البدء (يتطلب مفتاح المضيف) |
| `GET` | `/api/sessions/:code/dashboard` | الإحصاءات الكاملة (يتطلب مفتاح المضيف) |
| `GET` | `/api/sessions/:code/export` | تنزيل النتائج JSON (يتطلب مفتاح المضيف) |
| `DELETE` | `/api/sessions/:code` | إنهاء الجلسة ومحو بياناتها فوراً |
| `GET` | `/api/qr?text=…` | رمز QR بصيغة SVG |
| `GET` | `/j/:code` | رابط الدخول المختصر (هدف رمز QR) |

مفتاح المضيف يُمرَّر عبر الترويسة `X-Host-Token` أو المعامل `?hostToken=`.

### رسائل WebSocket (`/ws`)

**من المشارك:** `join` · `rejoin` · `answer` · `next` (الوضع الحر) · `reaction` · `leave`
**من المضيف:** `host:hello` · `host:start` · `host:skip` · `host:prev` · `host:goto` · `host:lock` · `host:results` · `host:leaderboard` · `host:end` · `host:kick` · `host:dashboard`
**من الخادم:** `state` · `joined` · `dashboard` · `reaction` · `answer:accepted` · `answer:rejected` · `session:closed` · `kicked` · `error`

## الحدود والحماية

- ٣٠٠ مشارك و٦٠ سؤالاً كحد أقصى لكل جلسة، و٥٠٠ جلسة متزامنة للخادم.
- كل المدخلات تُقصّر وتُنظّف من محارف التحكم على الخادم.
- الإجابة الصحيحة **لا تُرسل** للمشارك قبل كشف النتائج.
- في الوضع المجهول لا يُرسل اسم أو أفاتار مع الإجابات المفتوحة إطلاقاً.
- إجابة واحدة لكل مشارك لكل سؤال، وتُرفض بعد إغلاق السؤال.
- المشارك يُعرَّف بمفتاح سري عشوائي؛ لا يمكن انتحال هوية مشارك آخر.

## الملاحظات

- التطبيق يحتاج WebSocket — خلف بروكسي عكسي فعّل تمرير الترقية (`Upgrade`/`Connection`).
- عند تعدد نسخ الخادم يجب تثبيت الجلسة على نسخة واحدة (الحالة في ذاكرة العملية).
